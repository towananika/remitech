# 準備 / REEL

準備ページのREELを選ぶと `#/prep/reel` へ移動する。日付・SNSを含むURLをブックマークすれば直接開ける。独立した投稿タブは設けない。

`/editor` は既存ログインの社員・管理者だけが読み書きできる。一般会員・未ログインは拒否する。投稿データは Durable Object の `reel:week:*` に置き、公開 JSON や公開 `/book` には本文を入れない。

- 作者が別のAI等で用意した日英原稿を日付・SNSごとに登録する。画面を開いても文章は生成しない。週のテーマと流れを登録し、連続4週間の同一テーマを避ける。
- X と IG は別の短文（英語 X 240文字以内、IG 500文字以内）。2026年10月の提供原稿は参考のみで、原稿データは保存しない。
- HIBIKI の承認操作はない。作者は日英本文を編集し、NOBO は「問題なし」または英文の修正版を保存する。修正版があればコピー対象にし、元の英文も残す。
- NOBO確認後、または投稿日前日00:00（Asia/Seoul）から英語をコピーできる。未確認なら元の英文を使う。作者の本文変更でNOBO確認をリセットする。
- 画像プロンプトは現在の英文を含む指示文を端末内で組み立ててコピーし、画面には表示しない。外部AIへのAPI呼び出しは行わない。
- 予約は各SNSで実際に予約した後の手動記録。既存の `reel|日付|SNS|17:00` を共有し、予約タブの変更も読み直す。予約済みの文章は先に予約解除してから変更する。

## ローカル

既存チェックアウトを使う。ワークツリーを新設しない。

```sh
# /workspace/remitech
python3 -m http.server 8899 --bind 127.0.0.1
# 別のターミナル /workspace/remitech/worker
XDG_CONFIG_HOME=/workspace/.remitech-dev/config WRANGLER_SEND_METRICS=false \
  /workspace/.remitech-dev/node_modules/.bin/wrangler dev \
  --config wrangler.local.toml --local --ip 127.0.0.1 --port 8787 \
  --persist-to /workspace/.remitech-dev/state
```

ブラウザ起動前に localStorage の `remitech-chore-api` を `http://127.0.0.1:8787/chores` に設定する。ローカル設定にはAIを接続しない。手動登録・監修・競合・権限はテストで検証できる。

```sh
# /workspace/remitech
node --test tests/reel-workflow.test.mjs
```

`posts-preview.html` は公開できるデザイン確認用ページ。新しく用意したサンプルだけを表示し、実データ・会員情報は含めず、更新処理にも接続しない。本物の投稿タブの権限制限を変えない。

## 本番の初回反映

GitHub Pagesの公開とWorkerの公開は別。Workers AIへの接続は使用しない。共有保存APIを反映するには、既存Workerへの公開権限が必要。APIトークンをソース、コマンド引数、公開ファイルに書かない。

```sh
# /workspace/remitech/worker — 認証済みの環境でのみ
wrangler deploy
```

NOBOは既存のログイン画面から本人が通常の会員登録を行う。管理者は既存の会員管理画面で社員権限を付ける。追加の初期アカウントやパスワードは配布しない。Cloudflare経由の会員追加は行わない。

NOBO修正は専用ダイアログで入力する。入力のたびに、この端末のlocalStorageへアカウント・日付・SNS別の下書きを保存する。閉じる・再読み込み後も「保存した下書きから再開」で復元する。共有保存の成功が確認できたときだけダイアログを閉じ、下書きを削除する。通信失敗・古い版との競合では入力を残す。「この端末の下書き」と「共有保存済み」を区別する。共有保存には更新版Workerの反映が必要で、ブラウザの下書き保存だけでは他の端末へ同期しない。

修正ウィンドウ・共有保存・監修記録は社員または管理者に限定する。一般会員・未ログインはAPIでも拒否する。NOBO欄の修正者は実際のログインIDで記録する。

IG Story は posts.json の REEL.snippets を使い、25文字以内の既存フレーズをランダムコピーする。直前と同じ候補を避ける。X・IG本文やNOBO修正とは独立した操作で、共有保存APIに接続しない。

原稿形式: 平日XはFeed 1〜3＋Comment、平日IGはFeed 1＋Comment。土日は両方ともFeed 1だけ。各部分の日英原稿を分けて登録・修正・コピーできる。画像が必要という依頼があるまで、画像生成・画像プロンプトの操作は表示しない。

現在の対象期間は2026年11月1日まで。11月2日以降は作成・表示の対象に含めず、次回の依頼時に対象範囲を更新する。参考原稿をもとにした新稿は公開サンプルと混ぜず、別の非公開作業ファイルで渡す。

### 2026年10月27日〜11月1日の準備原稿

新しく書き直した日英原稿は、公開リポジトリに置かず、既存の非公開KVの
`reel:prepared:2026-10-27-11-01:v1` に `{version:1,weeks:[...]}` として登録する。
社員が `/editor` を開いたときに形式を検証し、Durable Objectへ一度だけ取り込む。
既存の原稿・NOBO修正・予約済み投稿は上書きしない。NOBO確認は未確認で開始する。
完了マーカーを原稿と同じトランザクションで保存するため、再アクセスで復元・重複しない。
